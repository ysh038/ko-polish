# ko-polish

ko-polish는 한국어 글을 다듬는 Claude 스킬입니다. 글을 영어로 번역하고 그 영어를 다시 한국어로 번역한 다음, AI가 쓴 글에 흔히 나타나는 구조적 버릇이 남아 있는지 검수합니다.

## 수정 예시

다음은 예시용으로 쓴 초안 한 문단을 역번역한 결과입니다.

초안:

> 캐시 적용 후 응답 속도를 재 봤는데, 평균 420ms에서 180ms로 떨어졌습니다. 다만 첫 요청은 여전히 느려서 체감은 반쪽입니다. 원인 후보 3개 중 DB 커넥션 쪽이 유력. 이 부분이 발목을 잡고 있어 다음 주 배포는 빠듯합니다.

영어 번역본:

> After we applied the cache, we measured the response time. The average response time decreased from 420ms to 180ms. However, the first request is still slow, so users will notice only part of the improvement. Of the three possible causes of the slow first request, the DB connection is the most likely cause. Because this problem has not been solved yet, it will be difficult to meet the deployment schedule for next week.

최종 글:

> 캐시를 적용한 뒤 응답 시간을 측정했습니다. 평균 응답 시간은 420ms에서 180ms로 줄었습니다. 다만 첫 요청은 여전히 느려서 사용자가 체감하는 개선 효과는 일부에 그칩니다. 첫 요청이 느린 원인으로 세 가지를 꼽을 수 있는데, 그중 DB 연결일 가능성이 가장 높습니다. 이 문제가 아직 해결되지 않아 다음 주 배포 일정에 여유가 없습니다.

구어 표현인 "재 봤는데"는 "측정했습니다"로 바뀌었고, 비유인 "체감은 반쪽"과 "발목을 잡고"는 뜻을 직접 적은 문장으로 바뀌었습니다. 명사만 남아 있던 "원인 후보 3개 중 DB 커넥션 쪽이 유력"에는 주어와 서술어가 채워졌습니다. 마지막 문장은 번역 직후 "일정을 맞추기는 어렵습니다"였는데, 초안의 "빠듯합니다"보다 강한 표현이어서 의미 대조 단계에서 "일정에 여유가 없습니다"로 되돌렸습니다.

구조 검수에서는 다음과 같은 문장을 고칩니다.

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 부정 대구 | 이는 방향의 문제가 아니라 완성도의 문제입니다. | 모달 컴포넌트를 아직 만들지 않아서 생긴 문제입니다. |
| 자문자답 | 그렇다면 왜 차이가 났을까요? 원인은 캐시에 있습니다. | 차이는 캐시에서 났습니다. |
| 과압축 | 색 40종 중 공통 4종 | 색상 40개 가운데 세 번의 결과에 공통으로 쓰인 것은 4개입니다. |
| 비유적 동사 | 주장이 힘을 잃습니다 | 주장이 약해집니다 |

## 이렇게 다듬는 이유

AI가 쓴 한국어 글에서 독자가 바로 알아차리는 문제는 어휘에도 있고 구조에도 있습니다. 둘은 고치는 방법이 달라서, 이 스킬은 역번역을 먼저 하고 구조 검수를 그다음에 합니다.

### 어휘는 역번역으로

AI는 "색 40종 중 공통 4종"처럼 조사와 주어를 지워 명사만 남기거나, "측정하다"를 쓸 자리에 "재다"를 씁니다. "주장이 힘을 잃는다"처럼 다른 대상에 쓰는 동사를 비유로 가져오기도 합니다.

초안을 영어로 옮기면 지워진 말이 다시 채워집니다. 영어 문장은 주어와 목적어 없이 쓸 수 없기 때문입니다. 이때 영어 번역본에는 관용구나 비유를 쓰지 않습니다. 영어 단계에서 들어간 비유는 한국어 번역에도 그대로 남습니다.

한국어로 다시 옮길 때는 초안을 보지 않습니다. 초안을 보면서 번역하면 초안의 표현을 다시 쓰게 됩니다. 영어 번역본만 보면 뜻은 이미 정해져 있으니 그 맥락에서 가장 통상적인 한국어 표현을 고르게 됩니다. 서브에이전트를 쓸 수 있는 환경에서는 초안을 본 적이 없는 서브에이전트에 이 단계를 맡깁니다.

글을 두 번 번역하면 의미가 조금 달라질 수 있어서, 코드, 명령어, 숫자, 고유명사처럼 바뀌면 안 되는 부분은 번역 대상에서 뺍니다. 마지막에는 최종 글을 초안과 비교하고, 의미가 달라진 곳을 모두 초안의 의미로 되돌립니다.

### 구조는 사후 검수로

"X가 아니라 Y입니다" 같은 틀, 항상 세 항목으로 된 나열, 항목마다 짧은 단언으로 끝나는 불릿은 번역을 거친 뒤에도 글에 남습니다. 번역은 문장 안의 표현을 바꾸지만 문장과 문단을 짜는 방식은 그대로 옮깁니다. 그래서 이 스킬은 번역이 끝난 뒤 `references/patterns.md`의 점검 항목 34개에 비추어 글을 검수합니다.

검수에서는 항목에 해당하는 곳만 고칩니다. 한 틀을 다른 틀로 바꾸지도 않습니다. 예를 들어 "X가 아니라 Y입니다"를 "X라기보다 Y입니다"로 바꾸지 않고 Y를 직접 서술합니다.

## 설치

이 안내는 Claude Code 기준입니다. 저장소를 개인 스킬 폴더에 클론합니다.

```bash
git clone https://github.com/ysh038/ko-polish ~/.claude/skills/ko-polish
```

프로젝트 하나에서만 스킬을 쓰려면 해당 프로젝트의 루트 폴더에서 다음 명령을 실행합니다.

```bash
git clone https://github.com/ysh038/ko-polish .claude/skills/ko-polish
```

설치한 뒤에는 Claude Code 세션을 새로 시작합니다. 슬래시 명령 목록에 `/ko-polish`가 보이면 설치가 끝났습니다.

스킬을 최신 버전으로 업데이트하려면 다음 명령을 실행합니다.

```bash
git -C ~/.claude/skills/ko-polish pull
```

스킬을 제거하려면 폴더를 삭제합니다.

```bash
rm -rf ~/.claude/skills/ko-polish
```

## 사용법

`/ko-polish`로 스킬을 호출합니다. 명령 뒤에 무엇이 오는지에 따라 동작이 달라집니다.

| 입력 | 동작 |
|---|---|
| `/ko-polish 이 PR 요약해 줘`처럼 요청을 붙인 경우 | 아래 절차에 따라 그 요청에 대한 답을 작성합니다. |
| 명령 뒤에 글을 붙인 경우 | 그 글을 다듬습니다. 내용을 더하거나 빼지 않습니다. |
| `/ko-polish`만 입력한 경우 | 직전 답변을 다듬을지 새 요청을 기다릴지 묻습니다. |

명령 없이 "AI 티 빼 줘", "번역투 없애 줘"처럼 요청해도 스킬이 실행됩니다. 보고서, 공유 문서, PR 설명, 메일처럼 다른 사람이 읽을 한국어 글을 써 달라고 요청할 때도 Claude가 이 스킬을 사용합니다.

기본 문체는 합쇼체(-습니다) 줄글입니다. 개조식(-함, -임)처럼 다른 문체를 지정하면 그 문체를 따릅니다. 초안과 영어 번역본은 답변에 표시되지 않으며, 보고 싶으면 따로 요청하면 됩니다.

한두 문장짜리 짧은 답변에서는 번역 단계를 건너뛰고 구조 검수만 수행합니다.

## 절차

1. 초안 작성. 한국어로 답을 쓰고 내용이 맞는지만 확인합니다.
2. 보호 구간 표시. 코드, 명령어, 파일 경로, 숫자, 날짜, 고유명사, 인용문, 사용자가 쓴 용어는 번역 대상에서 제외하고 적힌 그대로 둡니다.
3. 영어 번역. 생략된 주어와 목적어를 모두 채우고, 관용구나 비유 없이 뜻 그대로 씁니다.
4. 한국어 번역. 초안을 보지 않고 영어 번역본을 문장 단위로 옮깁니다. 서브에이전트를 쓸 수 있는 환경에서는 초안을 본 적 없는 서브에이전트가 이 단계를 수행합니다.
5. 구조 검수. 번역문을 `references/patterns.md`와 대조하고, 항목에 해당하는 곳만 고칩니다.
6. 의미 대조. 최종 글을 초안과 비교해 숫자, 이름, 부정 표현, 각 주장의 강도를 확인합니다. 둘이 다른 곳은 초안의 의미로 되돌립니다.
7. 출력. 최종 글만 내놓습니다.

전체 점검 목록은 `references/patterns.md`에 있습니다. 목록은 문장 구조(1~8번), 문단과 글 구조(9~17번), 한국어 어휘와 문법(18~27번), 글쓴이와 독자(28~34번)로 나뉩니다. 한 번만 나온 표현은 대체로 그대로 두고, 해당 항목에 허용된 횟수보다 자주 나올 때 고칩니다.

## 여기까지 읽으셨다면

이 README도 Claude가 ko-polish 절차로 쓴 글입니다. 여기까지 어색한 곳 없이 읽혔다면 이 글을 스킬이 내놓는 결과물의 한 예로 보시면 됩니다. 어색한 문장이 있었다면 [이슈](https://github.com/ysh038/ko-polish/issues)에 남겨 주세요. 점검 항목을 보완하는 데 반영하겠습니다.

## 스킬이 하지 않는 일

- 요청하지 않는 한 코드 블록 안의 주석은 바꾸지 않습니다.
- 글의 종류를 바꾸지 않습니다. 예를 들어 보고서를 에세이로 만들지 않습니다.
- 사용자가 직접 쓴 글을 다듬을 때는 사용자 고유의 표현 습관을 지우지 않습니다. 점검 목록은 AI가 쓴 글을 대상으로 만들었습니다.

```
ko-polish/
├── SKILL.md
├── references/

```

`SKILL.md`에는 Claude가 따르는 절차가 들어 있습니다. `references/patterns.md`에는 구조 검수에 쓰는 점검 목록이 들어 있습니다.
